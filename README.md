# ClinIQ — AI-Powered Cohort & Data Quality Explorer

> **Track 2 — Smarter Patient Care** | Sofstica Hackathon 2026  
> Transparent Research Prototypes from Structured Clinical Data

---

## What Is ClinIQ?

ClinIQ is a **research-only** prototype that helps clinical-data researchers, educators, and healthcare data teams explore, validate, and query the **MIMIC-IV Clinical Database Demo v2.2** (100 de-identified patient records from Beth Israel Deaconess Medical Center).

It provides three core tools:

| Tool | Purpose |
|------|---------|
| **Cohort Builder** | Type a plain-English research question and receive a validated SQL query, inclusion/exclusion criteria, patient count, and demographic breakdowns — all generated by an AI model (GPT-4o-mini) but executed and verified by deterministic backend logic. |
| **Data Quality Inspector** | Automatically scan 31 clinical tables for missing data, duplicates, implausible values, temporal misalignments, unit inconsistencies, and orphaned foreign keys — with a clear visual distinction between data errors and plausible clinical findings. |
| **Coverage Explorer** | Visualize measurement availability per table, per patient, and per column. Drill into any patient to see which data categories are present or absent. |

---

## Target User

Clinical-data researchers, educators, and healthcare data teams — **not** clinicians making patient-care decisions. This is stated prominently in a persistent, non-dismissible safety banner on every page.

### Data Flow (Cohort Builder)

1. User types a natural-language research question.
2. Backend sends **only schema metadata** (table names, columns, types, relationships) to the LLM — **no patient data ever leaves the system**.
3. LLM returns structured JSON with SQL, inclusion/exclusion criteria, and explanation.
4. Backend validates the SQL (SELECT-only, no injection, tables exist).
5. Backend executes the SQL against the local SQLite database.
6. Backend computes demographics (age distribution, gender, mortality) using Python.
7. Frontend displays results with provenance tooltips and an "AI Generated" badge.

### AI Method

- **Model**: OpenAI GPT-4o-mini (configurable via `LLM_MODEL` env var)
- **Prompting**: Schema-aware system prompt with 5 few-shot examples from pre-built templates
- **Temperature**: 0.1 (deterministic SQL generation)
- **Safety**: Clinical keyword tripwire blocks treatment/diagnosis questions before they reach the LLM
- **Fallback**: If the LLM API is unavailable, a keyword-based template matcher provides basic coverage
- **Transparency**: Generated SQL is fully visible, editable, and re-executable by the user

## Setup Instructions

### Prerequisites

- Python 3.10+ (with pip)
- Node.js 18+ (with npm)
- An OpenAI API key ([get one here](https://platform.openai.com/api-keys))

### 1. Clone the repository

```bash
git clone https://github.com/JaweriaAnwer/sofistica-2026--AI_for_Smarter_Patient_Care-.git
cd sofistica-2026--AI_for_Smarter_Patient_Care-
```

### 2. Set up the backend

```bash
# Install Python dependencies
pip install -r backend/requirements.txt

# Download and ingest the MIMIC-IV Demo dataset
python data/download_mimic.py
python data/ingest_to_sqlite.py

# Configure environment variables
copy backend\.env.example backend\.env
# Edit backend\.env and set your OPENAI_API_KEY

# Start the API server
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

### 3. Set up the frontend

```bash
cd frontend
npm install
npm run dev
```

### 4. Open the app

Navigate to **http://localhost:5173** in your browser.

## Reproducibility

- Evaluation scripts use `random.seed(42)` for deterministic results.
- The SQLite database is deterministically built from the same MIMIC-IV Demo v2.2 source CSVs.
- LLM calls use `temperature=0.1` to minimize non-determinism in SQL generation.

---

## Assumptions & Design Choices

1. **Read-only database access**: All SQL queries run with `PRAGMA query_only = ON`. The DQ engine flags issues but never modifies source data.
2. **Schema-only LLM context**: Only table/column metadata is sent to the LLM. No patient identifiers, values, or measurements are included in prompts.
3. **ICD version awareness**: The system handles both ICD-9 and ICD-10 codes, always specifying `icd_version` in queries.
4. **Date shifting**: MIMIC-IV dates are shifted for de-identification. The system does not attempt to infer real calendar dates or seasonality.
5. **100-patient demo subset**: Results are not representative of the full MIMIC-IV population. The system notes this limitation in the UI.
